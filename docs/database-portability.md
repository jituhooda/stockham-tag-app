# Database portability

The same code runs on SQLite and PostgreSQL. How that is kept true:

1. **One query layer.** All application SQL is built with SQLAlchemy Core
   (`crud.py`, `repositories/`), never raw dialect SQL.
2. **Per-dialect DDL, shared data.** `migrations/sqlite` and
   `migrations/postgres` hold the DDL for each version; `migrations/common`
   holds portable statements (reference data).
3. **Adapters** (`database/adapters/`) apply each engine's settings: SQLite
   gets `foreign_keys=ON`, WAL and a busy timeout; PostgreSQL gets pooling and
   `pool_pre_ping`, and any `postgres://` URL is normalised to psycopg 3.
4. **Rules** in `database/portability/compatibility-rules.json`; the checkable
   ones run in `tests/database-portability/migration`.
5. **The same tests on both.** `tests/database-portability/{sqlite,postgres}`
   run identical checks (clean migration, schema = code = model, constraints,
   decimals). The whole backend suite also runs on PostgreSQL:

```bash
cd backend
TEST_DATABASE_URL=postgresql+psycopg://… uv run pytest            # backend suite on PG
TEST_POSTGRES_URL=postgresql+psycopg://… uv run pytest ../tests   # PG portability tests
```

## Known differences (and how the app handles them)

| Topic | SQLite | PostgreSQL | Handling |
| --- | --- | --- | --- |
| Timestamps | naive text | `TIMESTAMPTZ` | app writes UTC; reads are normalised with `as_utc` |
| `VARCHAR(n)` | not enforced | enforced | API validates lengths first |
| `NUMERIC` | REAL affinity | exact | 2-decimal values only; API rounds |
| Booleans | 0/1 | true/false | SQLAlchemy `Boolean` |
| Identity | `AUTOINCREMENT` | `GENERATED BY DEFAULT AS IDENTITY` | sequences reset after `db-switch` |

## Switching SQLite → PostgreSQL

```bash
createdb stockham_tags
scripts/db-switch.sh postgres postgresql+psycopg://stockham:…@db:5432/stockham_tags
# then set DATABASE_URL to that value and restart the API
```

The script backs up first, migrates the target, refuses a non-empty target,
copies every table in foreign-key order in one transaction, resets identity
sequences, and verifies the result. Attachments stay where they are.
